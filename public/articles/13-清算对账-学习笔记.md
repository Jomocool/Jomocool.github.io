## 三、核心设计

### 1. 内部对账（同系统内核对）

用「成交明细」重算「持仓」（买入 − 卖出），与记录持仓对比。不一致说明数据漂移。

### 2. 外部对账（与交易所核对）

两份成交列表按 `tradeId` 关联，找出三种差异：

| 差异 | 含义 |
|------|------|
| 缺失 missing | 交易所有、我方无（漏记） |
| 多余 extra | 我方有、交易所无（多记） |
| 金额不符 mismatch | 都有但价格/数量对不上 |

### 3. K 线聚合（OHLCV）

把成交按**时间桶**（如 1 分钟）聚合：
`开`=第一笔价、`高`=最高价、`低`=最低价、`收`=最后一笔价、`量`=总成交量。

### 4. 日终清算

收盘后批处理，汇总全天：总成交量、总成交额、全天 OHLC。

## 四、关键决策

| 决策 | 原因 |
|------|------|
| 对账按 `tradeId` 关联 | 成交编号是双方共有的唯一键 |
| K 线用 `ts / bucketSeconds` 分桶 | 整数运算，桶起点可还原 |
| OHLC 增量更新 | 单次遍历 O(n)，high/low 取极值、close 取末值 |
| 金额整数运算 | 延续整数避免浮点原则 |
