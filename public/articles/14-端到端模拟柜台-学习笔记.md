## 一、阶段 13 要解决什么

把前 12 个阶段的所有模块**收口**成一个可演示的完整系统：

1. **柜台 API**：一个门面类整合风控 + 资金 + 撮合 + 持仓
2. **模拟行情生成器**：随机游走
3. **可观测性**：指标（延迟/吞吐）+ 健康检查
4. **端到端链路**：开户 → 入金 → 下单 → 成交 → 持仓 → 清算

## 三、核心设计

### 1. 柜台门面（Facade 模式）

```
Counter（门面）
 ├─ RiskEngine（风控）      ← 下单前检查
 ├─ AccountManager（资金）  ← 冻结/扣款
 ├─ MatchingEngine（撮合）  ← 撮合成交
 └─ 持仓表                  ← 买卖更新
```

下单流程：**风控 → 冻结 → 撮合 → 双向结算 + 持仓更新**。

### 2. 模拟行情生成器

随机游走：每步在 ±N tick 内随机，价格围绕中间价波动。

### 3. 可观测性

- **指标**：下单数、拒单数、成交笔数、平均/最大延迟
- **健康检查**：一行汇总当前状态

## 四、关键决策

| 决策 | 原因 |
|------|------|
| 柜台用门面模式整合各模块 | 对外一个简洁 API，对内屏蔽复杂度 |
| 指标在调用点记录延迟 | 精准测量单笔处理耗时 |
| 模块源码直接编译复用 | 避免跨项目链接依赖 |
